Technology

Every tool, chosen for a reason

A production-oriented stack covering data engineering, vector search, LLM orchestration, and cloud deployment — each component justified by the problem it solves.

01 Data Engineering
DatabricksUnified Analytics Platform
Managed Spark environment used to ingest, clean, and transform the raw Airbnb CSV dataset. Unity Catalog provides a governed data lakehouse with table versioning and lineage tracking.
PySpark
Unity CatalogData Governance
Centralized metadata store that catalogues the raw, silver, and gold-tier tables produced during transformation. Enables fine-grained access control and audit trails.
Delta Lake
Inside AirbnbSource Dataset
Publicly available dataset containing 35,036 Airbnb listings across Sydney, including property descriptions, pricing, host information, and review scores — the ground truth for semantic search.
35,036 rows
02 Vector Search
BAAI/bge-small-en-v1.5Embedding Model
A compact 33M-parameter bi-encoder producing 384-dimensional dense vectors. Trained with contrastive learning, it consistently outperforms models 3× its size on retrieval benchmarks. Runs locally, with no inference cost.
384-d
SupabaseVector Database
PostgreSQL-hosted vector store using the pgvector extension. Each listing description is stored as a 384-dimensional float array alongside structured metadata, enabling hybrid relational + semantic queries.
pgvector
HNSW IndexApproximate Nearest Neighbour
Hierarchical Navigable Small World graph index built over the embedding column. HNSW trades a small recall cost for sub-millisecond similarity search at scale, making real-time vector retrieval practical.
O(log n)
03 AI Agent
LangGraphAgent Orchestration
Stateful graph framework used to implement a ReAct (Reason + Act) agent loop. The agent cycles through thought → tool call → observation steps until it has enough information to synthesise a final recommendation.
ReAct
DeepSeek-ChatLanguage Model
Frontier-class LLM accessed via OpenAI-compatible API. Powers the reasoning loop — deciding when to invoke tools, interpreting results, and generating the final natural-language recommendation.
via OpenAI SDK
Custom GuardrailsInput / Output Validation
Two-pass validation layer applied before the agent sees a query and after it generates a response. Blocks toxicity, off-topic queries (non-accommodation requests), and competitor brand mentions from appearing in output.
Safety Layer
04 Observability
LangSmithLLM Tracing
Full execution trace for every agent run: token counts, latency per node, tool call inputs and outputs, and a waterfall view of the LangGraph execution. Enables debugging without re-running the agent.
Full traces
05 Deployment
FastAPIWeb API
Async Python web framework serving the agent as a REST endpoint. Handles CORS, request validation via Pydantic, and static file serving for the frontend — all in a single deployable process.
Python 3.11
DockerContainerisation
The entire application — API, embedding model, guardrails, and frontend — is packaged as a single immutable container image. Eliminates environment drift between local development and production.
Multi-stage build
GitHub ActionsCI/CD Pipeline
Automated workflow triggered on every push to main: builds the Docker image, pushes it to Azure Container Registry, and deploys the new revision to Azure Container Apps — zero-downtime rolling update.
deploy.yml
Azure Container AppsHosting
Serverless container hosting with built-in HTTPS termination, custom domain support, and auto-scaling from zero. Billing is per-request, making it cost-effective for a portfolio project with variable traffic.
Live endpoint
